# Agent 3: 碎片表达与风格DNA

## 来源类型
LofiSu 的碎片表达主要来自：
1. GitHub Profile README（累计150次提交的高频迭代文本）
2. PR/Issue的英文描述正文
3. 小红书帖子（未直接获取，通过第三方报告间接了解）

## 高频用词与句式

### GitHub README用词特征
- **身份关键词密度极高**：AI Full-Stack、Apache Committer、Maintainer、Contributor
- **机构名称高频出现**：Apache、ByteDance、Tencent、Alibaba — 构成"背书矩阵"
- **技术赛道标签密集**：Agent、MCP、workflow、low-code、AI Infra、RL
- **求职市场术语**：Currently looking for a full‑stack AI agent developer position、Douyin AI4SE RL&Infra

### PR/Issue英文正本风格
- **直译感/模板感**：中文思维直译英文的痕迹明显
- **拼写错误**：navigatior (navigator)、偶尔run-on sentence
- **提议句式为主**：I can write one、I can try to pull request、如果社区需要我可以做这个
- **缺乏技术讨论深度**：正本多为"做了什么"而非"为什么这样做"

### 表达策略模式
1. **并列打包法**：将强弱差异很大的几段经历并列排在一起，制造"每项都很扎实"的整体印象
2. **关键词堆积**：在README中用密集的关键词构建身份矩阵
3. **省略边界**：写"Contributor"但不写明贡献体量和类型，让读者自行脑补
4. **身份迭代**：README高频修改反映的不是技术成长，而是市场定位的调整

## 争议立场
- 将自己定位为AI Infra/Full-Stack，但公开最强贡献集中在网站前端和文档
- 称自己"Maintainer of ByteDance/DeerFlow"，但DeerFlow公开的core authors中无其名
- 在简历中并列Higress/OpenYurt，但这两个项目主仓库公开证据为0

## 幽默方式
无明显幽默感体现在公开记录中。表达风格以"职业化个人品牌建设"为主，严肃、目标导向。

## 确定性表达
高确定性、断言型表达。使用"I can"、"I will"而非"I might"、"perhaps"。身份声明都用陈述句，不带不确定修饰。

## 语言切换
- 面向技术社区（GitHub）：英文为主，质量"够用"
- 面向中文受众（小红书）：中文为主，用于卖课和圈钱

## 关键发现

### 表达DNA的核心特征
1. **身份先行**：每句话在表达"我是谁"之前已经定义了"谁在说话"
2. **关键词密度**：单位文字中身份标签/机构名称的比例极高
3. **省略的艺术**：不说假话，但省略那些会减弱印象的关键限定词
4. **市场导向**：所有表达最终服务于"被市场更高估值"

### 与通用AI的区别
- AI倾向于用完整描述、限定词、不确定性表达
- LofiSu倾向于省略限定、并列强弱、让读者自行完成印象升级

## 可信度评估
- 一手来源：README原文、PR/issue正文 — 可信度高
- 二手来源：调查报告的分析 — 基于事实的分析，质量高
