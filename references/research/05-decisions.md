# Agent 5: 决策记录与行动

## 来源类型
LofiSu的决策记录主要通过GitHub公开行为轨迹推断，覆盖其身份经营、项目选择、关系管理等多个维度。

## 关键决策与行为模式

### 决策1: 选择GitHub Profile README作为主战场
- 行为：将个人profile仓库的README迭代150次，占总commit的一半以上
- 决策逻辑：Profile README是GitHub上最容易被看到的页面，等同于免费的个人品牌广告位
- 事后验证：到2026年3月，README已从一个谦逊的"前端学习者"自我介绍演化为高密度的身份资产展示

### 决策2: 从"做事情"转向"经营身份"
- 时间线：2024年初为"前端学习者"，2024年中为"前端工程师+开源爱好者"，2026年3月集中重写为"AI Full-Stack/Apache Committer/DeerFlow Maintainer"
- 关键转折：2026-03-09一天修改README 13次，完成身份叙事的集中重构
- 决策逻辑：不是等待身份自然形成，而是主动设计身份并反向填充证据

### 决策3: 选择性进入高势能项目
- 她选择参与的项目：Apache Fory（Apache品牌）、DeerFlow（ByteDance+AI Agent）、Omi（Tencent）、Spring AI Alibaba（Alibaba+AI）
- 她参与的方式：优先选择前端/官网/文档类贡献路径（最容易展示、技术准入门槛最低）
- 她放弃的：主仓库核心逻辑、底层引擎、需要深度技术积累的模块
- 决策逻辑：选最容易进入但最具品牌势能的项目+每个项目中选最快能产出可见成果的模块

### 决策4: Issue先于PR——先占位后做事
延续性动作模式：
1. 先在项目中发起issue，表达"这个可以做什么"和"我可以做"
2. 然后提交PR落实issue中的提议
3. 将PR和issue一起写入个人履历

典型案例：
- Apache Fory Site #139: 提国际化配置issue → PR #141 落实
- Apache Fory Site #149: 提team page issue → PR #152 落实
- OpenYurt #441: 提AOS动画issue → 表示"我可以做"

### 决策5: Fork就是参与——高势能贴附策略
- Fork了约50个高势能仓库（deer-flow、OpenViking、codex、claude-code、spring-ai-alibaba、playwright-mcp等）
- 原创仓库约13个，且多为博客/笔记/demo类内容
- 结构：大量fork构成"赛道贴附层"，少量原创内容构成"持续产出感"
- 决策逻辑：不需要在每个仓库都有实质性贡献，fork列表本身就是"我在这个赛道上"的信号

### 决策6: 将开源参与转化为商业变现
- 在GitHub建立技术叙事身份后，到小红书平台利用该身份卖课
- 身份包装 → 流量获取 → 变现金流
- 这是一条完整的商业模式，GitHub不只是技术参与平台，更是品牌制造工厂

### 决策7: 快速迭代社交关系
根据调查报告作者描述：
- 不是稳定建立关系，而是快速扫描、接近、筛选、丢弃
- connection是资源操作工具而非关系本身
- 这种模式在开源社区和私下社交中被观察到是一致的

## 决策特征总结

1. **低风险高可见度**：选项目中最容易被看到的工作类型（前端/官网/文档）
2. **先行占位**：不等别人分配角色，主动用issue建立"我在参与"的visibility
3. **叙事主导行动**：不是做了什么写什么，而是想成为什么就去排布什么
4. **工具性思维**：项目、头衔、关系都是上升材料
5. **资源最大化**：用有限的真实产出撬动最大的身份溢价

## 可信度评估
- 一手来源：GitHub公开记录（commit、PR、issue、repo结构） — 可信度高
- 二手来源：调查报告作者的一次私下互动描述 — 单方证词
- 推测：小红书卖课的具体操作细节 — 用户陈述，无独立验证
